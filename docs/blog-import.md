# 블로그 작업사례 1차 이전

2026-09-16, 소유자 요청에 따라 네이버 블로그 `97ga074`의 실제 정비 글 10편을 홈페이지 형식으로 정리했다.

- 초안 데이터: `src/lib/data/blog-drafts.json`
- 홈페이지용 사진: `public/blog-imports/` — 72장, 약 16MB. 네이버 본문용 966px 이미지이며 생성 이미지가 아니다.
- 원문 주소·제목·발행일·사진 출처·확인 메모를 데이터의 `source`에 보관했다.
- 모든 준비 데이터는 `status: draft`, `is_published: false`, `published_at: null`이다.
- 준비 데이터는 공개되지 않으며 아래의 관리자 공개 기능을 통해 운영 DB에 저장한다. 블로그 원문에서 가져온 글이 아닌 BMW 730LD 사례는 소유자 요청으로 운영 사이트의 휴지통으로 이동했다.

## 로컬 확인

```sh
npm run build
BLOG_IMPORT_PREVIEW=1 npm start -- --hostname 127.0.0.1 --port 3089
```

`/works`에서 목록·검색·상세를 확인한다. 홈페이지는 대표 사례 1편과 후속 사례 3편을 보여 주고 전체 목록으로 연결한다. 미리보기 안내 및 noindex를 적용하며 초안 조회수는 DB에 기록하지 않는다. 환경 변수를 생략하거나 `0`으로 설정하면 기존 공개 데이터만 표시한다. 이 변수는 운영 배포에 설정하지 않는다. 사이트맵과 RSS에는 로컬 초안을 추가하지 않는다.

## 관리자 공개 및 임시저장

`/admin/works` → **블로그 작업사례 가져오기** → **블로그 10편을 실제 사이트에 공개**. 검토용으로 저장하려면 **임시저장만 하기**를 사용한다.

관리자 로그인이 필요하다. 서버에서 권한을 다시 확인한 후 준비된 데이터만 저장하며, 클라이언트에서 본문을 전달받지 않는다. 기존 글은 ID·슬러그·네이버 원문 주소로 확인한다. 임시저장은 기존 글을 건너뛰며, 공개는 기존 본문·제목·사진을 보존하면서 분류와 공개 상태만 반영한다. 반복 실행과 일부 실패 시 재시도가 가능하다. 사진은 프로젝트와 함께 배포되어야 한다.

공개 시 원문의 발행일을 유지하며 noindex를 해제하고 홈페이지·목록·상세·사이트맵·RSS를 갱신한다. DB의 작업사례 확장 필드가 누락된 경우 내용을 버리고 저장하지 않고 실패를 표시한다.

## 복합 정비 분류

대표 서비스는 기존 `service_id`에 유지하고 함께 진행한 서비스는 `general_tags`에 정식 서비스명으로 저장한다. 새 DB 마이그레이션은 필요하지 않다. 카드·상세·홈페이지에는 모든 분류를 표시하고 서비스별 목록은 대표 또는 추가 분류 중 하나에 해당하면 포함한다. 관리자 편집기에 추가 서비스 체크박스를 제공한다.

- 흡기 4편: 스포티지, 푸조, 모하비, 맥스크루즈.
- 인젝터 3편: 스포티지, 푸조, 맥스크루즈.
- DPF 3편: SM5, 모하비, 맥스크루즈.
- 맥스크루즈는 위 세 분류에 모두 포함된다. 전체 글은 중복 없이 10편이다.

## 검증

- `node scripts/check-blog-import.mjs`: 기본 비노출, 초안 상태, 사진 경로, 원문 연결, 서로 다른 네이버 URL 형식의 중복 방지, 기존 글 보존, 검색·서비스 필터·페이지 분할.
- TypeScript, ESLint, Next.js 운영 빌드.
- 로컬 HTTP: 10개 상세 200, 미리보기 해제 시 초안 404, 관리자 로그인 이동, 사이트맵·RSS 초안 제외.
- 브라우저: 상세 사진·원문 링크, 모바일 390px 가로 넘침 없음.
- 사진 72장 모두 최대 변 966px 이상인지 확인하고 원문 사진과 본문 순서를 대조했다.

수집 원본 HTML과 재실행 도구, 기존 파일 백업은 바탕화면 업무 폴더의 `blog-import/`에 보관했다. 이 기능은 선별된 10편의 이전 기능이며 블로그 전체를 주기적으로 자동 동기화하는 기능은 아니다.
